为什么是 PCL-In

相比上游 PCL Community Edition (PCL CE) 的主要改动。

去除强制正版验证

使用第三方皮肤站（Authlib / Yggdrasil Connect）或离线档案的玩家，不再被强制进入「试玩模式」，可直接正常游戏。

去除所有赞助提示

不弹出赞助窗口，也不引导用户访问原作者的爱发电，界面更干净。

独立更新机制

通过 GitHub Releases API 检测本仓库的新版本，不会覆盖你的 fork 改动。

功能特性

完整继承 PCL CE 的启动器能力，并针对非正版玩家优化验证方式。

第三方皮肤站

支持 Authlib 与 Yggdrasil Connect，可接入第三方验证服务器与皮肤站，正版玩家亦可正常使用。

离线验证

内建离线账号，无需联网即可登录，适合局域网、单机或快速测试。

微软正版登录

使用 OAuth 设备码流完成正版验证，无需填写应用密钥，在浏览器中授权即可。

完整的启动器能力

继承 PCL CE 的版本下载与安装、整合包、资源与 Mod 管理、多实例等完整功能。

多语言

提供简体中文、繁体中文与英文界面，可随时切换。

开源

代码公开托管于 GitHub，根目录遵循 Apache-2.0，可自由查看与二次开发。

系统要求

运行 PCL-In 前请确认你的环境满足以下条件。

  • 操作系统：Windows 10 1809（build 17763）或更高版本
  • 运行环境：.NET 10 Desktop Runtime
  • 处理器架构：x64（Intel / AMD）或 ARM64

常见问题

PCL-In 和 PCL2 / PCL CE 是什么关系？

PCL-In 是基于 PCL Community Edition (PCL CE) 的二次 fork，由 PCL-In 独立开发与维护。上游 PCL CE 又源自 PCL2。

用第三方皮肤站或离线档案会被强制「试玩模式」吗？

不会。这是 PCL-In 相对上游最核心的改动：使用第三方皮肤站（Authlib / Yggdrasil Connect）或离线档案时，不再被强制进入试玩模式。

正版登录需要填写应用密钥吗？

不需要。微软正版登录采用 OAuth 设备码流（RFC 8628），属于公开客户端，只需一个公开的 client_id，在浏览器中授权即可，启动器不保存任何密钥。

运行时提示缺少 .NET 怎么办？

请安装 .NET 10 Desktop Runtime（不是 ASP.NET Core 或仅 .NET Runtime）。系统需为 Windows 10 1809 (17763) 或更高。

如何反馈问题或提交建议？

请前往 GitHub Issues 提交，附上启动器日志与复现步骤会更快得到处理。
