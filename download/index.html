与上游 PCL CE 的差异

PCL-In 只改动验证与更新相关的行为，其余启动器能力与上游保持一致。

功能

继承 PCL CE 的全部启动器能力，并针对非正版玩家的验证方式做了调整。

第三方皮肤站

支持 Authlib 与 Yggdrasil Connect，可接入第三方验证服务器与皮肤站；正版玩家同样能正常登录。

离线验证

内建离线档案，无需联网即可进入游戏，适合单机、局域网与快速测试。

微软正版登录

使用 OAuth 2.0 设备码流（RFC 8628）完成验证：只需公开的 client_id，在浏览器里输入设备码即可，启动器不保存任何应用密钥。

完整的启动器能力

版本下载与安装、整合包导入、Mod 与资源包管理、多实例与存档管理，全部来自上游 PCL CE。

多语言界面

提供简体中文、繁体中文与英文三套界面，可在设置中随时切换。

开源

代码托管于 GitHub，根目录遵循 Apache-2.0，可自行查看、构建与二次开发。

常见问题

PCL-In 和 PCL2 / PCL CE 是什么关系？

PCL-In 是基于 PCL Community Edition (PCL CE) 的二次 fork，由本仓库独立开发与维护；上游 PCL CE 又源自 PCL2。

用第三方皮肤站或离线档案会被强制「试玩模式」吗？

不会。这是 PCL-In 相对上游最核心的改动：使用第三方皮肤站（Authlib / Yggdrasil Connect）或离线档案时，不再被强制进入试玩模式，可直接正常游戏。

正版登录需要填写应用密钥吗？

不需要。微软登录采用 OAuth 2.0 设备码流（RFC 8628），属于公开客户端，只需要一个公开的 client_id：启动器显示一个设备码，你在浏览器中登录并授权即可，程序内不保存任何 secret。

怎么确认下载的文件没有被篡改？

在下载目录打开终端执行 certutil -hashfile PCL-In-x64.exe SHA256，把结果与下载页「SHA256」按钮复制到的哈希值比对；也可以导入仓库中的 GPG 公钥后校验 .asc 签名。

如何反馈问题或提交建议？

请前往 GitHub Issues 提交，附上启动器日志（设置 → 日志）与复现步骤会更快得到处理。
